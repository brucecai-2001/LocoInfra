# 训练与评测

> 一句话：先在仿真里学一个"会预测机器人下一刻状态"的世界模型，再让控制策略在这个世界模型里"想象"接下来几十步，并沿着想象轨迹直接求梯度来改进自己。
>
> 代码在 `infra/SuperMimic-Q1/`：在 [SuperMimic](https://arxiv.org/abs/2610.28480) 的开源复现 [SuperMimic-Reproduced](https://github.com/CuboiLeo/SuperMimic-Reproduced)（Unitree G1）的基础上改造成支持 Q1、加入了双 Encoder 基础动作模型、物理随机化、省力约束和完整验收评测。环境变量 `SUPERMIMIC_ROBOT=q1|g1` 切换机器人。

## 0. 环境

训练需要 NVIDIA GPU（我们用过 RTX 5090 和 H800；4096 个并行仿真环境约需 20 GB 显存）。

```bash
bash infra/setup.sh                       # 先克隆 infra/.deps/mjlab
cd infra/SuperMimic-Q1
uv sync --group dev                       # Python 3.12，torch（CUDA 13）、mujoco 3.16、warp、mjlab
uv pip install onnx onnxruntime           # 导出权重包需要
SUPERMIMIC_ROBOT=q1 env -u PYTHONPATH .venv/bin/pytest tests -q
```

若系统 `PYTHONPATH` 带有 ROS 的 Python 3.10 包，会让 pytest 崩溃，命令前加 `env -u PYTHONPATH`。单元测试需要先按 [数据处理](data.md#8-转成训练格式-motionnpz) 准备 `data/npz/q1_walk/`（几段 LAFAN 走路即可）。

## 1. 训练算法：SuperMimic

### 1.1 基本思路

普通强化学习（如 PPO）只能靠"试错 + 打分"间接估计梯度，很慢。SuperMimic 换了个思路：

1. **先学一个世界模型**：一个神经网络，输入"当前状态 + 动作 + 这次仿真的物理参数 \(\xi\)"，输出"下一刻的状态"。它是可微的；
2. **在想象里训练策略**：从真实仿真里采一批起点，让策略在世界模型里往前推演 32 步。奖励、摔倒判定都写成状态的可微函数，于是"策略参数 → 动作 → 下一状态 → 奖励"整条链都能反传梯度（BPTT，通过时间反向传播）；
3. **两者交替**：4096 个仿真环境持续用当前策略采数据，存进回放池；世界模型从回放池学，策略在世界模型里学。

策略目标（SHAC 式）：

\[
J=\mathbb{E}\Big[\sum_{t=0}^{H-1}\gamma^t c_t\,r_{t+1}+\gamma^H c_H\,V(s_H)\Big],\qquad c_t=\prod_{k\le t}\big(1-\sigma(\ell_k)\big)
\]

其中 \(H=32\)，\(c_t\) 是世界模型终止头给出的"存活概率"，\(V\) 是 critic 对想象终点的价值估计（用带终止概率的 λ-return 拟合）。

### 1.2 世界模型

| 部分 | 设计 |
|---|---|
| 输入 | 去掉航向的规范化状态（骨盆高度、6D 姿态、航向系线速度、骨盆系角速度、关节角、关节速度）+ 当前动作 + **上一步动作** + 归一化的 \(\xi\) |
| 为什么要上一步动作 | 有指令延迟时，新指令发出后的头几个物理小步里电机还在执行旧指令 |
| 网络 | 3 层 2048 宽 MLP（SiLU） |
| 输出 | 56 维状态增量，按物理积分（速度先更新、位置用新速度积分）；最后一层零初始化，所以训练从"匀速外推"这个物理先验开始 |
| 终止头 | 输入骨盆高度差、倾斜差（各除阈值）→ 小 MLP → 摔倒 logit |
| 训练 | **8 步自回归**：从窗口首状态出发、用记录的实际执行动作连续滚 8 步，每步与真实状态比归一化误差，加终止 BCE。多步训练让长时预测不发散 |

奖励、观测、终止特征都是状态的解析函数（`world_model/heads.py`），仿真侧和想象侧共用同一份代码；刚体位姿由可微正运动学（`kinematics/g1_fk.py`，按 MuJoCo 模型构建，与 MuJoCo 一致到 1e-10）算出。

### 1.3 Q1 适配

维度全部由关节数 \(N_J=22\) 推出（`robot.py`）：

| 量 | 维数 | 组成 |
|---|---|---|
| 状态 `s` | 57 | qpos 29 + qvel 28（根角速度在骨盆系） |
| 单帧本体观测 | 72 | 关节角 − 站姿 22、关节速度 22、骨盆角速度 3、重力方向 3、上一步动作 22 |
| 策略观测 | 720 | 10 帧历史，按项分块（同一项的 10 帧连续放，从旧到新） |
| 每帧参考特征 | 54 | 关节角 − 站姿 22、关节速度 22、重力 3、骨盆角速度 3、航向系线速度 3、骨盆高 1 |
| 仿真上下文 \(\xi\) | 34 | 脚摩擦 1、关节零偏 22、质心偏移 3、物理缩放与延迟 8 |

| 部分 | 设计 |
|---|---|
| 执行器 | PD 位置控制。刚度 kp：髋 / 膝 80、腰 60、踝 40、臂 30 N·m/rad；峰值力矩 35 / 22 N·m；转子惯量 0.004。`Q1_PD=vendor_getup` 切换为起身 / 趴下用的低增益（髋膝 30），其他增益组可加到 `robots/q1.py` 的 `PD_PRESETS` |
| 动作 | PD 目标 = 站姿 + 0.25 × 动作 − 编码器偏置；站姿微屈膝，骨盆高 0.445 m |
| 碰撞 | 身体外形只和地面碰撞（凸包在关节处互相重叠，开自碰撞会一直报碰）；脚底 4 个小球接触 |
| 控制周期 | 物理步长 5 ms × 4 = 20 ms（50 Hz） |
| 观测 | 只有真机能拿到的量：关节编码器、骨盆 IMU、上一步动作。**不给相对位置**（真机没有全局定位），只给"参考躯干相对机器人躯干的朝向"6 维 |
| 摔倒判定 | 骨盆高度与参考差 > 0.15 m 或倾斜差 > 0.8；片段播完算超时（不是失败） |
| 规模 | 4096 个仿真环境；每次想象 4096 条 × 32 步；每步梯度出现 NaN / Inf 就跳过 |

### 1.4 随机化

每个环境每类参数只抽一个标量（所有关节共用），都写进 \(\xi\)。**世界模型看得到 \(\xi\)**，所以能在想象里模拟"这台机器人电机偏软"；**策略看不到 \(\xi\)**，只能学会对各种情况都应付得了。

| 类别 | 范围 | 何时变 |
|---|---|---|
| 论文原有 | 脚摩擦 0.3–1.2、关节零位偏差 ±0.01 rad、躯干质心偏移 ±1.5 / 2 / 2 cm | 每回合 |
| 质量 / 惯量 | ±10%；转子惯量 ±20% | 启动时（改它要重算模型；4096 个环境各不相同，本身就覆盖了范围） |
| 电机 | kp、kd、力矩上限 ±20%；关节摩擦 0–0.3 N·m | 每回合 |
| 延迟 | 指令延迟 0–20 ms、传感器延迟 0–20 ms | 每回合 |

传感器延迟在想象里同样模拟（观测历史每帧换成与上一帧的线性插值），保证策略在想象和仿真里看到的东西分布一致。动作在执行时加高斯噪声（std 0.1），回放池存实际执行的动作，世界模型拟合的就是实际执行的动作。

### 1.5 奖励

主要是"跟得像不像"——BeyondMimic 式跟踪项（根和 14 个跟踪刚体的相对位置 / 朝向 / 线速度 / 角速度，均为 \(\exp(-\text{err}/\sigma^2)\)），参考先整体平移旋转到与机器人躯干同一水平位置和航向，全局漂移不影响刚体项。另加"动作别抖""别撞限位"和三项省力约束：

- 力矩不要太大：\(-0.02\sum(\tau/\tau_\text{peak})^2\)
- 功率不要太大：\(-10^{-4}\sum\lvert\tau\dot q\rvert\)
- 尽量别超额定力矩：\(-0.05\sum\mathrm{relu}(\lvert\tau\rvert/\tau_\text{rated}-1)^2\)（电机长时间超额定会过热）

三项加起来只占每步满分的约 1%，只起约束作用。Q1 没有手腕，手的朝向误差权重降到 0.2。

**训练里没有"推一把"**：为了让世界模型好学，论文去掉了外力推搡，抗推能力只来自随机化和初始姿态扰动。这是已知短板。

### 1.6 起点采样

每个片段切成 1 s 的小段，每段维护折扣回报的滑动平均。重置时 50% 均匀采样、40% 按 \(\mathrm{softmax}(-25\cdot\text{回报}/g_\text{max})\) 多采做得差的段、10% 难度记忆。重置在参考状态上加位姿 / 速度 / 关节噪声。

## 2. 基础动作模型

### 2.1 结构

\[
z_t=\begin{cases}E_\text{ref}(b_t) & \text{照着参考做}\\ E_\text{tele}(s_t,m_t,o_{t-9:t}) & \text{听命令做}\end{cases}\qquad a_t=D(z_t,o_{t-9:t})
\]

（\(b\) 参考动作，\(s\) 槽位，\(m\) 掩码，\(o\) 最近 10 帧本体观测，\(a\) 关节动作。）

| 部分 | 网络 | 说明 |
|---|---|---|
| `E_ref` | MLP(2048, 1024, 512, 256) → 32，tanh | 只看参考，不看本体状态 |
| `E_tele` | 每个槽位单独线性投影到 64 维 + 槽位类型嵌入，乘掩码后**求和池化**；池化向量 + 掩码 + 观测历史 → MLP(512, 512) → 32，tanh | 加新槽位只多一个投影，主干输入宽度不变，旧权重能直接加载 |
| `D` | MLP(2048, 1024, 512, 256) → 22，最后一层增益 0.01 | 两个 Encoder 共用 |
| `z` | 32 维 | 两个 Encoder 与 Decoder 之间的"通用语言" |
| critic | MLP(256, 128)，输入规范化状态、目标、\(\xi\)、根误差 | 三类批次各一个，只在训练时用 |

所有输入缩放都做在网络内部（`register_buffer`），部署时直接喂物理量。只用矩阵乘、加法和简单激活，机器人板上的 ONNX Runtime 能跑。

**关键设计：Decoder 只被 `E_ref` 的训练更新。** 训练 `E_tele` 时临时把除 `E_tele` 外的所有参数设为不求梯度，梯度**穿过** Decoder 到达 `E_tele`，但 Decoder 权重不动。因此：

- 命令驱动的动作"长相"永远来自动作库里的真人动作；
- 命令侧怎么改（加槽位、换映射、续训）都碰不到参考跟踪能力；
- 反过来，动作库里没有的动作，命令也做不出来——解决办法是补数据给 `E_ref`。

### 2.2 参考输入 `body_ref`

| 项 | 定义 |
|---|---|
| 每帧 | 54 维参考特征（见 1.3） |
| 看几帧 | 未来 4 帧：机器人在参考第 \(i\) 帧时，取 \(i+1\) 到 \(i+4\) 帧；超出末尾重复最后一帧 |
| 另加 | 参考躯干相对机器人躯干的朝向 6 维（6D 旋转表示，不含位置） |
| 总维数 | 4 × 54 + 6 = 222 |

单段动作策略用未来 10 帧（546 维），与论文一致。

### 2.3 命令槽位

槽位是 `E_tele` 的"输入表格"，定义在注册表 `supermimic/tele/slots.py`（带版本号）。导出时 `deploy.yaml` 的槽位表和 ONNX 输入布局都由它生成，保证训练和部署对得上。

| 槽位 | 维数 | 含义（Q1 尺度、Q1 坐标系） | 不填时的默认值 |
|---|---|---|---|
| `base` | 3 | 航向系前进 / 侧移速度 vx、vy，转身角速度 wz | 0（站着不动） |
| `height` | 1 | 骨盆相对标准站高（0.434 m）的偏移，即下蹲量 Δh | 0 |
| `torso` | 3 | 躯干系下的重力方向（表示前后 / 左右倾斜，与航向无关） | (0, 0, −1)，直立 |
| `hand_L` / `hand_R` | 3 + 3 | 手相对"头"（躯干上方 0.2625 m）的位置，躯干航向系 | 动作库中位数，手自然下垂 |
| `feet` | 6 | 预留（接腿部追踪器后启用），目前恒为不填 | — |

送进网络前每个值先减默认值、除以尺度、乘掩码。设计规则：

- **只追加，不修改、不删除、不重排**：老的权重包永远能加载；要"删"一个槽位就让它永远不填；
- **掩码只表示填没填**：置信度、控制模式之类另开槽位；
- **旋转不用欧拉角**（会跳变）：躯干用重力方向表示；
- **高度用相对值**：不用头显的绝对高度。

### 2.4 从参考动作生成命令标签

训练 `E_tele` 需要知道"如果有人在遥控这段动作，他当时会给出什么命令"。这些标签从**重定向之后的 Q1 动作**里算出来（`tele/labels.py`），所有数据源都用同一套算法：

```text
Q1 参考动作
  ├─ 骨盆水平速度、转身速度 → base（前后共 25 帧居中平均，约 0.5 s 平滑）
  ├─ 骨盆高度              → height（同样平滑）
  ├─ 躯干倾斜              → torso（同样平滑）
  ├─ 左右手位置（正运动学） → hand_L、hand_R
  └─ 完整全身动作          → body_ref，以及打分用的标准答案
```

平滑是为了不让模型把动捕抖动当成真实命令。

**`tele_ok` 标记**：有些动作光靠这几个槽位描述不清，比如踢腿、交叉步——脚怎么动是槽位里没有的信息。所以逐帧打标记，以下情况及其前后 0.5 s 标为"不可只靠命令复现"：脚抬高 > 12 cm、双脚腾空 ≥ 0.1 s、交叉步、平面速度 > 1.2 m/s 或转速 > 2 rad/s、片段名含 dance。这些帧不用来训练 `E_tele` 的模仿，但仍给 `E_ref` 训练。每 1 s 小段还按"走 / 转 / 蹲 / 倾 / 动手"五类打标签，供均衡采样（动作库里走路占大头，不均衡的话 `E_tele` 只会走路）。

### 2.5 三类训练批次

4096 个环境分三类，各有一个 critic：

| 类型 | 占比 | 给模型什么 | 怎么打分 | 改哪部分 |
|---|---|---|---|---|
| 参考跟踪 | 50% | 完整参考 `body_ref` | 全身跟参考像不像 | `E_ref` + Decoder |
| 模仿（蒸馏） | 25% | 从参考算出的槽位 | 同样看全身像不像；另加 \(0.1\lVert z_\text{tele}-\mathrm{sg}(z_\text{ref})\rVert^2\) 让两个 Encoder 的 `z` 对齐 | 只改 `E_tele` |
| 自由命令 | 25% | 随机生成或从片段读的命令 | 命令完成得好不好 + 平衡、省力、平滑 | 只改 `E_tele` |

**模仿**相当于让 `E_tele` 向 `E_ref` 学：同一段动作，`E_ref` 看完整参考，`E_tele` 只看几个槽位，要做出一样的效果。起点只从 `tele_ok` 的位置采（一半按命令类别均衡），想象到 `tele_ok = 否` 的帧就停。

**自由命令**让 `E_tele` 响应任意命令，而不只是复现动作库：

- 命令一半读当前片段的槽位，一半随机：前进 −0.6 到 1.0 m/s、侧移 ±0.5 m/s、转身 ±1.5 rad/s；下蹲 −0.15 到 +0.02 m（目标高度以 0.25 m/s 渐变）；前倾 −0.15 到 0.6 rad、侧倾 ±0.25 rad；双手位置从动作库 `tele_ok` 帧里取（保证够得着）。每 5 秒换一次；
- 打分：速度和转向各 2 分、高度 1 分、躯干 1 分、每只手 0.75 分，偏差越小分越高；没填的槽位按 0.3 倍权重奖励"回到默认值"（这样追踪丢失时自然退回站立、手自然下垂）；再加两项腿部姿态惩罚——髋 yaw 偏离站姿超过 0.1 rad 的平方（权重 −4）、两脚横向间距不足 14 cm（权重 −5）。没有这两项时自由行走会退化成外八、两脚踩一条线；
- 摔倒判定以"按命令高度站直"的虚拟姿态为基准，所以命令下蹲不会被误判为摔倒。

**随机丢槽位**：每个命令周期，每个槽位 15% 概率被屏蔽；另有 25% 的时间只给 `base`（模拟只用摇杆）。

一次策略更新的顺序：冻结世界模型和 critic → 参考批次想象、反传、更新 `E_ref` 与 Decoder → 模仿 / 自由批次想象、只更新 `E_tele`（新 critic 先单独预热 300 次更新）→ 梯度先按范数 1.0、再按值 0.1 裁剪，任一组梯度非有限就整步跳过 → 三个 critic 各自拟合。

## 3. 训练流程

所有命令在 `infra/SuperMimic-Q1/` 下运行，日志和检查点写到 `logs/<run 名>/`。

### 3.1 单段动作（验证工具链、做技能）

```bash
scripts/train/single.sh walk1_s1 data/npz/walk1_s1
```

未来 10 帧参考 + 躯干相对朝向。每 15 分钟做一次整条评测，不摔且回报 ≥ 0.80 就停，最多 3 小时。实践发现只看这一项会停得偏早，建议训满 1–1.5 小时（加 `--schedule.no-stop-on-pass --schedule.max-hours 1.5`）。

### 3.2 基础动作模型（两阶段）

```bash
# 第一阶段：E_ref + Decoder 从零训练
scripts/train/base_ref.sh base_ref data/npz/mix_v1
# 第二阶段：加入 E_tele（蒸馏 + 自由命令），从第一阶段续训
scripts/train/base_dual.sh base_dual data/npz/mix_v1 logs/base_ref/ckpt_latest.pt
```

两阶段的观测口径必须一致（`--env.anchor-obs --env.anchor-ori-only --env.future-frames 4`）。第二阶段默认学习率 1e-4、余弦衰减重新走一遍，6.5 h 上限，每小时整条评测一次。

我们发布的模型（dual_v3b）实际经过了更多轮续训：从零训练完整参考接口（7.2 h）→ 加入命令接口并扩到 33 h 动作库（约 14 h）→ 合并为双 Encoder（6.5 h）→ 收紧速度奖励（4.5 h）→ 加腿部姿态惩罚（约 2 h）。上面两阶段脚本是这条路径的精简版，最后的默认值都已写进 `TeleCfg` 和脚本。各轮的数字见 [实验结果](results.md)。

### 3.3 常用参数

`sm-train --help` 列出全部选项（`config.py`，tyro）。常用的：

| 参数 | 作用 |
|---|---|
| `--resume <ckpt>` | 续训；\(\xi\) 维数变了会自动给世界模型 / critic 第一层补零列；旧检查点缺 `E_tele` 时自动初始化 |
| `--schedule.lr-from-resume` | 从续训点重新走一遍余弦学习率 |
| `--schedule.max-hours` / `--schedule.total-iterations` | 停止条件 |
| `--schedule.eval-interval-min` | 每隔多少分钟做整条确定性评测 |
| `--data.clips a b` | 只用部分片段 |
| `--env.num-envs` | 并行环境数（显存不够时调小） |
| `--reward.w-extra-contact` / `--reward.w-impact` | 多余接触与撞击速度惩罚（默认关闭，贴地、倒地类动作用） |

多卡：`torchrun --nproc-per-node N .venv/bin/sm-train ...`，参数广播 + 梯度 all-reduce，学习率 × √N。

## 4. 评测与验收

所有评测都在真实仿真里跑，不看世界模型的想象结果。

### 4.1 评测脚本

| 脚本 | 测什么 |
|---|---|
| `scripts/eval_benchmark.py` | 整条确定性播放：每段从首帧放到尾，无噪声无随机化，报告归一化回报和摔倒数 |
| `scripts/eval_report.py` | 单段动作完整验收（确定性、全随机化 1000 回合、推搡、换求解器）→ `report.json` + `report.html` + 回放视频 |
| `scripts/eval_library.py` | 留出集整条播放，`E_ref` 和 `E_tele`（可测多种槽位组合，如 `--masks all base,height,torso`） |
| `scripts/eval_tele.py` | 命令阶跃：从站立给速度 / 高度 / 躯干 / 双手命令，取最后 2 s 与命令比；逐个屏蔽槽位 |
| `scripts/eval_tele_robust.py` | 命令状态下的推搡恢复，以及 kp / kd / 惯量 / 力矩上限偏移下的速度跟踪 |
| `scripts/eval_tele_stress.py` | 快速切换、反向、摇杆噪声、手移动、反复下蹲、槽位丢失等时变命令 |
| `scripts/eval_push.py` | 推搡恢复（静态 T 姿参考） |
| `scripts/render_policy.py` / `scripts/play.py` | 离屏渲染视频 / 交互式回放（半透明为参考） |

### 4.2 单段动作的合格线

| 测什么 | 怎么测 | 合格线 |
|---|---|---|
| 完整播放 | 首帧到尾，无噪声无随机化 | 回报 ≥ 0.80，不摔 |
| 随机条件下的稳定性 | 1000 次随机起点、最长 10 s，全部随机化 + 传感器噪声 + 初始扰动 | 摔倒 ≤ 1% |
| 被推后恢复 | 慢速时刻先跟 1 s，再给骨盆随机方向 0.5 / 1.0 / 1.5 m/s 的速度，3 s 内不摔算恢复，每档 64 次 | 全部恢复 |
| 力矩峰值 | 看控制器"想要"的力矩（仿真会截断实际力矩，看实际值发现不了超限） | 不超峰值 |
| 超额定时间 | 各关节超额定的累计时间，对比可行性检查的估算 | ≤ 估算 × 1.2 + 0.2 s |
| 关节误差 | 完整播放全程平均 | ≤ 0.1 rad |
| 换仿真参数 | 换摩擦模型和求解器、步长减半 | 回报下降 < 10%，不摔 |

不合格时可以把动作放慢（时间拉长 1.2–1.5 倍）、删掉做不了的片段，或多训一会。

### 4.3 基础动作模型的合格线

| 测什么 | 合格线 |
|---|---|
| 留出集完整播放 | 回报 ≥ 0.75、摔倒 ≤ 5%；另报告手位置误差和命令误差 |
| 缺槽位 | 逐个屏蔽槽位都不摔，自然退回站立 / 手自然下垂 |
| 速度 / 高度 / 躯干命令 | 前进、后退、侧移、转身、组合、回零、下蹲、起身都不摔；不能出现没让它弯腰它却弯腰 |
| 双手 | 站、蹲、走、转身时分别测，慢速时手位置误差 < 5 cm |
| 被推 | 0.5–2.0 m/s（站立、慢走）都能恢复 |
| 电机参数偏 ±20% | 跟踪误差变大不超过 20% |
| 两种用法切换 | 带 `z` 平滑过渡，不摔 |
| 板上推理 | 50 Hz |

当前模型各项的实测见 [实验结果](results.md)。
